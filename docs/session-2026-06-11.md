### 4. 캘린더 이월 버그 수정 — 전전년도 carry 누락

**커밋:** `cbe5784`

**문제**
- 새해(1월) 캘린더에서 이월 잔여 휴가가 0으로 초기화되는 현상
- 예: Aradhya Mishra — Dec 2025에서 2.7일 잔여 표시 → Jan 2026에서 0으로 리셋

**원인 분석**
```
기존 로직:
  carryover_2026 = min(5, max(0, calcAccrued(2025) - taken_2025))
                 = min(5, max(0, 10 - 10)) = 0  ← WRONG

올바른 로직:
  2024 carry → 2025에 +2.7 추가됨
  실제 2025 가용 = 10 + 2.7 = 12.7
  실제 잔여 = 12.7 - 10 = 2.7
  carryover_2026 = min(5, 2.7) = 2.7  ✓
```

**수정 내용** (`app/hr/components/AttendanceGrid.tsx`)
- Promise.all에 `year-2` leave entries 쿼리 추가 (`prevPrevYe`)
- prevCarryover 계산 후 prevTotalAvail에 반영:
```typescript
const prevPrevAccrued = calcAccrued(emp, year - 2, 12)
const prevCarryover   = Math.min(5, Math.max(0, prevPrevAccrued - prevPrevVac[emp.id]))
const prevAccrued     = calcAccrued(emp, year - 1, 12)
const prevTotalAvail  = prevAccrued + prevCarryover
coMap[emp.id] = Math.min(5, Math.max(0, prevTotalAvail - prevVac[emp.id]))
```

### 5. 연차 주기별 통계 리팩토링 + 접기/펼치기 히스토리 테이블

**커밋:** `2ea8d5a`

**배경**
- 기존 `loadStats`: 3개의 개별 쿼리 (calendar year, current period, prev period)
- 문제: 3년차 이상에서 carryover가 정확하지 않음 (AttendanceGrid와 동일한 multi-year carry 누락 버그)
- 요구사항: 각 입사 주기별(Year 1, Year 2, ...) 적립/이월/사용/잔여/소멸 통계 표시

**수정 내용** (`app/hr/components/EmployeeSearch.tsx`)

새 타입 및 헬퍼 함수:

  periodYear: number; periodStart: Date; periodEnd: Date

function getAllAnnivPeriods(startDateIso: string): AnnivPeriod[]
// 입사일부터 현재까지 모든 주기를 배열로 반환

`loadStats` 재설계:
- 기존 3개 쿼리 → 2개로 축소 (calendar year + **입사일부터 현재까지 모든 vacation entries**)
- 단일 쿼리로 가져온 데이터를 클라이언트에서 주기별로 분류
- **Cascade 계산**: Year 1 carryOut → Year 2 carryIn → ... 순으로 연쇄 계산
```typescript
for (let i = 0; i < periods.length; i++) {
  const used      = vacEntries.filter(e => e.date >= pStartIso && e.date <= pEndIso).reduce(...)
  const accrued   = isCurrent ? calcAccruedInPeriod(...) : emp.vacation_allowance
  const remaining = max(0, accrued + carryIn - used)
  const carryOut  = isCurrent ? 0 : min(5, remaining)
  const expired   = isCurrent ? 0 : max(0, remaining - 5)
  carryIn = carryOut  // ← cascade
}
```

## 버그 패턴 정리

| 버그 유형 | 원인 | 해결 방식 |
|-----------|------|-----------|
| Active 탭 terminated 표시 | `is_active=true`지만 `end_date` 있는 데이터 불일치 | 서버 쿼리 + 클라이언트 이중 필터 |
| 캘린더 퇴사자 다음달 표시 | `is_active=true` 조건이 `end_date` 무시 | `end_date.is.null` OR `end_date.gte.firstDay`로 변경 |
| Probation 중 적립 미반영 | AttendanceGrid.tsx에만 구 로직 잔존 | probation 블록 제거, 입사일 기준으로 통일 |
| 신년 이월 초기화 | `carryover = accrued - taken`에서 전전년도 carry 미포함 | year-2 데이터 추가 쿼리, cascade 반영 |
| Multi-year carryover 오류 | 이월 계산이 2년치만 봄 | 입사일 이후 전체 데이터 1회 쿼리 + cascade |

## 데이터 불일치 주의사항

Supabase `employees` 테이블에서 발생할 수 있는 불일치:

| 상황 | is_active | end_date | 처리 |
|------|-----------|----------|------|
| 정상 활성 | true | null | Active 탭 표시 |
| 정상 퇴사 | false | 날짜 | Terminated 탭 표시 |
| **불일치** | true | 날짜 | Terminated 탭 표시 (클라이언트 필터) |
| **불일치** | false | null | 캘린더에서 제외 (end_date.is.null 조건) |

→ 클라이언트 레벨 이중 필터로 데이터 불일치 방어 처리됨
