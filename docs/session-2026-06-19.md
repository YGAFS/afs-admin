### 2. 연차 적립 계산 일 단위 기준으로 변경

**커밋:** `5b2748c`

**문제**
- 기존 로직: 완성된 월수만 카운트 → 6개월 × 0.833 = 5.00일
- 유저 기대: 부분 월 포함 일할 계산 → 192일 / 365 × 10 = 5.26일

**수정 내용** (`app/hr/components/EmployeeSearch.tsx`)

```typescript
// 이전 (월 단위)
function calcAccruedInPeriod(allowance: number, periodStart: Date): number {
  let months = (today.getFullYear() - periodStart.getFullYear()) * 12
             + (today.getMonth() - periodStart.getMonth())
  if (today.getDate() < periodStart.getDate()) months--
  return Math.round(Math.max(0, months) * (allowance / 12) * 100) / 100
}

// 이후 (일 단위)
function calcAccruedInPeriod(allowance: number, periodStart: Date): number {
  const daysElapsed = Math.floor((today.getTime() - periodStart.getTime()) / 86400000)
  return Math.round(Math.max(0, daysElapsed) / 365 * allowance * 100) / 100
}
```

### 5. Upsert 에러 핸들링 수정 (깜빡임 버그)

**커밋:** `58c7d86`

**문제**
- OT 등록 시 잠깐 표시 후 사라지는 버그
- 원인: `upsert()` 결과 에러를 확인하지 않고 무조건 optimistic update 적용 → DB 거부 후 `load()`가 실제 데이터로 덮어씀

**수정 내용** (`app/hr/components/AttendanceGrid.tsx`)

```typescript
// 이전 — 에러 무시
await supabase.from('leave_entries').upsert(...)
setLeaveMap(p => ({ ...p, [key]: { code, hours } }))

// 이후 — 에러 체크 후 실패 시 alert
const { error } = await supabase.from('leave_entries').upsert(...)
if (error) { alert(`저장 실패: ${error.message}`); setSaving(false); return }
setLeaveMap(p => ({ ...p, [key]: { code, hours } }))
```

### 6. DB CHECK 제약 조건 수정 (미완료 → 수동 실행 필요)

**문제**
- `leave_entries_leave_code_check` 제약에 `'O'`가 없어서 Supabase에서 거부
- 에러: `new row for relation "leave_entries" violates check constraint "leave_entries_leave_code_check"`

**해결 방법** — Supabase SQL Editor에서 실행:

```sql
ALTER TABLE leave_entries DROP CONSTRAINT leave_entries_leave_code_check;

ALTER TABLE leave_entries ADD CONSTRAINT leave_entries_leave_code_check
  CHECK (leave_code IN ('L','L1','L2','L3','S','S1','S2','S3','W','W1','W2','W3','T','T1','T2','T3','B','O'));
```

파일 저장 위치: `supabase/add_overtime_leave_code.sql`
