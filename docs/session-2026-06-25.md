### 1. 이메일 To 주소 `encodeURIComponent` 버그 수정

**커밋:** `6cbb7fa`

**문제**
- 수신자 이메일이 `user@domain.com` 형식임에도 Outlook에서 `domain.com` (도메인만) 으로 표시되며 "Email address is not valid" 오류 발생
- 원인: `openMailto()`에서 To 이메일 주소를 `encodeURIComponent()`로 인코딩 → `@` → `%40` 변환 → Outlook이 파싱 실패

**수정 내용** (`app/hr/[company]/page.tsx`)

```typescript
// 이전 — @ 가 %40 으로 인코딩되어 Outlook 파싱 실패
`mailto:${encodeURIComponent(recipient?.email ?? '')}?subject=...`

// 이후 — To 주소는 raw 그대로 전달 (subject/body만 인코딩)
const toEmail = recipient?.email ?? ''
`mailto:${toEmail}?subject=${encodeURIComponent(subject)}&body=${encodeURIComponent(body)}`
```

**규칙:** `mailto:` URL에서 To 이메일 주소 자체는 절대 `encodeURIComponent` 금지. `subject`·`body` 파라미터만 인코딩.

### 2. ContactMgr 이메일 형식 유효성 검사 추가

**커밋:** `f8ca126`

**문제**
- 이메일 입력란에 `afstransco.com` (도메인만, `@` 없음) 으로 저장하는 실수 발생
- 잘못된 이메일이 저장되어도 오류 없이 진행됨

**수정 내용** (`app/hr/[company]/page.tsx` — `ContactMgr` 컴포넌트)

- `validEmail(e: string)` 함수: `@` 포함 여부 + 도메인에 `.` 포함 여부 검사
- 유효하지 않은 이메일은 추가/수정 저장 버튼 비활성화
- 입력 중 실시간 빨간 테두리 + `"user@domain.com 형식 필요"` 안내
- 기존 저장된 잘못된 이메일에는 드롭다운에 `⚠️` 표시 + 목록에 주황색 `"← 수정 필요"` 표시
