## 6. Post-deploy bug fixes

Two immediate post-deploy issues were addressed.

### 6.1 English-first UI direction

Problem:

- large parts of the app were authored with Korean UI copy even though the team’s primary working language is not Korean

Fix direction implemented:

- added a lightweight UI language state in `app/providers.tsx`
- introduced `warehousing/lib/i18n.ts`
- made English the default UI language
- added an admin-only language toggle in `app/admin/page.tsx`
- restricted Korean UI switching to `admin@afstransco.com`

Files updated for this first pass:

- `warehousing/app/providers.tsx`
- `warehousing/app/admin/page.tsx`
- `warehousing/app/login/page.tsx`
- `warehousing/app/requests/new/page.tsx`
- `warehousing/components/RequestForm.tsx`
- `warehousing/app/components/Shell.tsx`
- `warehousing/lib/i18n.ts`

Important note:

- this pass established the global language mechanism and converted the most visible entry/admin/request-creation surfaces
- some secondary screens still retain Korean strings and need a second cleanup pass for full English/Korean parity

### 6.2 Sidebar active-state bug

Problem:

- when the user opened `/requests/new`, the sidebar highlighted both:
  - `New Request`
  - `Purchase Requests`

Cause:

- nav active matching used a broad `startsWith()` rule

Fix:

- rewrote nav active-state matching in `warehousing/app/components/Shell.tsx`
- `/requests/new` now matches only the new-request item
- `/requests` matches the list page and request detail pages, but not `/requests/new`
